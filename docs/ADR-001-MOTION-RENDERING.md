# ADR-001 — Motion Engine Option B: Blender-rendered 3D loops

**Status:** Accepted for pilot · **Date:** 2026-11-15 · **Issue:** https://github.com/Dmitriy-Bondarev/utro7/issues/2

## Context

The previous SVG instructor is a cartoon composed of vector bones and does not communicate human biomechanics convincingly. User chose Option B: create 3D instructors, animate each exercise in a controlled environment, and serve pre-rendered silent videos inside the existing PWA. Reference Seven is limited to the UX pattern; its visual assets, characters, text and motion clips are not used.

## Decision

1. Use Blender to author original 3D scenes, motions, characters and lighting.
2. Render **silent 560×560 H.264 / MP4 clips**, 20 fps, 2-second seamless loops for the pilot; add JPG posters.
3. Use the selected avatar (male/female) and exercise ID to resolve a versioned MP4 and poster. Use `autoplay muted playsinline loop` for Safari compatibility.
4. Keep existing SVG demonstration as **fallback** when an exercise has no 3D video or when media fails.
5. Keep music in WebAudio (never include it in exercise MP4); pause/resume video with workout timer.
6. Preserve all current UX, habit tracking, and offline PWA capabilities; media is loaded on demand, not pre-cached, so the offline fallback is SVG.
7. Source and generated Blender scenes remain editable and are committed to GitHub.

These assets demonstrate the production pipeline and show movement rather than a static pose. **They are intentionally stylized, simple 3D geometry** and do not yet approach the realism or instructional quality of Seven. The current movement trajectories are hand-authored and are not medical/fitness-coach-validated.

## Build and verification

Requires Blender 5.3, Python as bundled with Blender, FFmpeg with libx264, and 6 source scenes.
- Render and encode: `bash tools/blender/build_media.sh`.
- Files: `assets/motion/v1/<avatar>-<exercise>.{blend,mp4,jpg}`.
- Verify all exports: `python3 tools/blender/verify_media.py`.
- Browser test: `PUPPETEER_PATH=/path/to/puppeteer node tests/motion-smoke.cjs`.
- Existing regression: `PUPPETEER_PATH=/path/to/puppeteer node tests/smoke.cjs`.

## Reasons and tradeoffs

**Benefits:** compatibility with iOS without WebGL load, deterministic motion, consistent graphics, independently replaceable content, offline SVG fallback, manageable encoding sizes.

**Costs:** each avatar/exercise needs a separate encoded video; pose and camera are fixed inside each clip; real rigged human modelling and biomechanically valid motion remain separate production tasks; video offline cache is not yet guaranteed.

## Next quality gates before claiming Seven-like fidelity

1. Replace simple ellipsoid prototype bodies with professionally modelled and skinned humanoids (evaluate MPFB/MakeHuman and carefully licensed other assets).
2. Implement appropriate humanoid skeleton/IK for knees, shoulders, spine, wrists and ankle/foot contact.
3. Review 3 key motions (march/squat/pushup) with a qualified trainer; record corrections and technique notes.
4. Render stable previews at target iPhone size with enough visible figure area; test repeated loops, no hand/foot penetration and stable framing.
5. Validate Safari (real iPhone), low-power mode, muted autoplay, audio coexistence and video decode speed.
6. Scale from 3 to 12+ reviewed exercises, then to the 20+ exercise goal.
